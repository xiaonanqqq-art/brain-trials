# 脑力试炼综合闯关游戏设计方案

本项目制作一个中文单人益智游戏，玩家在浏览器中完成 15 道逐步变难的关卡，体验推理、观察和记忆挑战。源码发布到 GitHub，游玩入口通过 GitHub Pages 提供。

## 已确定的方向与建议

用户已选择综合闯关，并要求发布到 GitHub。2026-10-27 用户回复“开始吧”，同意按本方案进入开发。浏览器平台、名称“脑力试炼”、具体关卡数量、视觉风格和下述规则采用本方案的默认选择。

当前工作目录为空，没有既有技术栈或项目需要兼容。首版使用 HTML、CSS、JavaScript 制作静态网页，所有运行资源随游戏提供，无需后端或登录。开发工具的具体选择留给实现阶段，但最终产物必须可部署到 GitHub Pages 的项目子路径。

## 目标与范围

- 电脑和手机均可操作，进入首页后可直接开始或继续。
- 首版有 15 个固定关卡，每类 3 关，目标每局约 5 至 10 分钟；关闭计时后可慢慢思考。
- 支持提示、跳题、答案解析、练习重试、继续进度和本机最高分。
- 游戏分数体现本局表现，结果页不将其换算为标准 IQ 数值。
- 首版不包含账号、多人对战、云存档、全球排行榜、支付和原生安装包。

## 方案比较

| 玩法 | 体验与取舍 | 选择 |
| --- | --- | --- |
| 综合闯关 | 多类挑战交替出现，适合短局体验；需要统一不同题型的操作反馈 | 用户已选 |
| 烧脑解谜 | 连续剧情与复杂谜题更有沉浸感；首版内容制作较重 | 暂不采用 |
| 限时挑战 | 节奏快、适合刷分；时间压力更强 | 首版仅保留可关闭的计时 |

实现方式建议采用静态网页，适合此次单人题库和 GitHub Pages 发布。游戏引擎导出网页也是可行方案，但首版无需物理模拟或复杂场景，原生网页更易维护。桌面安装版增加了打包与分发工作，留作后续需求。

## 关卡设计

分为入门、进阶、挑战三章，每章各含下表中的五种题型，难度逐章提高。首版固定题库、固定顺序，先保证答案准确和解析清楚。

| 题型 | 主要交互 | 难度递进 |
| --- | --- | --- |
| 数字规律 | 从四个数字中选择答案 | 等差或递增差值、交替规律、两步关系 |
| 图形推理 | 从四个图形中选择答案 | 形状与数量变化、旋转、组合规则 |
| 逻辑判断 | 根据有限条件选择唯一结论 | 排序、真假陈述、条件排除 |
| 记忆挑战 | 观察亮格后，在网格中选出相同位置并提交 | 3×3 网格记 3 格、4×4 记 4 格、4×4 记 5 格 |
| 空间想象 | 观察明确标注的图形并选择答案 | 旋转、镜像、简单展开图 |

具体题面与图形由实现者编写。每题必须有唯一的预期选项、一个不直接泄露答案的提示、逐步解析。数字规律题明确约束规则，避免仅凭少量数字声称存在唯一数学延伸；空间题明确观察方向，避免依赖模糊的透视。全部题目需人工推演或独立校验。

记忆关观察时间为 5 秒；点击“准备好了”后才开始展示。观察结束隐藏图案，然后允许作答并开始答题计时。按记忆中的位置选择，重复点击可取消，必须选择指定数量才能提交；位置完全一致算正确。提示仅提供记忆策略，不再次展示图案。

## 流程与页面

首页显示游戏介绍、开始挑战、继续进度、模式选择与本机最佳成绩。新开一局时可选择计时或不限时，模式在本局内固定。

关卡页按三章展示全部关卡。首次挑战从第一关开始，结算当前关后才进入下一关，答错或跳过也能前进；未到达的关卡显示锁定。已经结算的关卡可以单独练习，练习成绩不计入整局记录。

答题页显示关卡编号、题型、题面、交互区、提示和跳过按钮。选择答案后需点击提交，提交后锁定答案并显示正确结果、解析与本关得分，由玩家点击下一关。

第 15 关结算后进入成绩页，显示总分、正确数、用时、五类题目的正确数、使用提示次数及错题回顾；提供重新挑战和练习错题入口。没有错题时显示通关反馈并隐藏错题练习入口。

## 计分与计时

每关首次结算只记录一次，答错、跳过和超时都得 0 分并显示解析。练习重试不修改原始成绩。

- 答对基础分 100 分。
- 每题最多用一次提示，答对时扣 30 分；提示不改变倒计时。
- 计时模式每关限 45 秒，答对额外得到 `floor(40 × 剩余毫秒 / 45000)` 分，范围 0 至 40。
- 不限时模式没有速度加分。
- 计时模式满分 2100 分，不限时模式满分 1500 分，分别保存最佳记录并明确标注模式。
- 记忆题的观察阶段、解析页、暂停页不计入答题用时。
- 暂停时隐藏题面和记忆图案；切换到其他标签页自动暂停，返回后需手动继续。该规则用于休闲游戏体验，不承诺竞技防作弊。
- 点击提交时以实际剩余时间判定；到达截止时间按超时处理，重复点击不能重复结算。

## 存档与异常处理

使用浏览器 localStorage 保存版本号、模式、关卡索引、当前阶段、已选答案或格子、提示状态、剩余观察和答题时间、已结算结果及各模式最佳记录。进入新阶段、交互变化、暂停和离开页面时保存，并定期保存计时进度。

刷新或关闭后恢复为暂停状态，玩家点击继续再计时。记忆题恢复到原阶段和剩余观察时间，不重新获得完整的观察时间。浏览器异常退出时允许丢失最近一次保存之后的少量计时进度，最多约 1 秒。通关清除进行中的存档并保留成绩记录。

存储不可用时仍能正常游玩，在界面说明本次进度无法保存。存档损坏或版本不兼容时安全忽略，不阻止开始新游戏；本机记录不跨设备同步。

## 视觉与操作

采用清晰的卡片布局、深蓝底色和明亮强调色，三章有可区分的进度表现。图形使用 CSS 或 SVG 绘制，题目不依赖外部图片、字体或网络接口。

支持触屏和鼠标，主要按钮有清晰的键盘焦点。正确和错误同时使用文字、图标与颜色表达。窄屏保持题面与选项可读；动效遵循减少动态效果偏好。具体排版、配色细节和轻量过渡效果由实现者决定。

## GitHub 发布

交付包含完整源码、运行与发布说明、静态发布文件和必要配置。所有静态资源使用相对路径或正确的项目基础路径，首页入口为 index.html。直接进入或刷新主页面正常显示。

先在本地完成和验证游戏，再确定 GitHub 账号、目标仓库与可见性，上传源码并启用 GitHub Pages；发布后打开真实网址验证游戏、资源和存档功能。仓库名称暂建议 brain-trials，实际使用用户确认的目标，不覆盖已有项目。

GitHub Desktop 是可选的图形化上传工具；是否使用取决于用户习惯和已授权的发布工具。GitHub Pages 负责在线托管。GitHub Free 可为公开仓库提供 Pages；选择这条免费发布路线意味着游戏源码公开。若用户希望私有源码，发布前另行核对其账号可用的方案。

可选扩展是将同一份网页产物打包 ZIP 后发布到 itch.io，本次不自动发布到该平台。

## 开发顺序与验收

1. 编写并核对 15 个关卡与解析，验证各题唯一预期答案。
2. 完成首页、关卡选择、答题和成绩页面，适配桌面与手机。
3. 实现题型交互、计时、提示、计分、练习和存档。
4. 验证完整通关、答错、跳过、超时、暂停、刷新续玩及记忆阶段恢复；核对得分边界和重复提交。
5. 检查桌面及手机尺寸、键盘操作、减少动效与不可用存储时的行为。
6. 准备 GitHub 发布文件与说明，部署后验证真实游玩网址，交付仓库和游戏两个链接。

设计已确认，进入具体实现计划与编码；发布状态以开发验证记录为准。
